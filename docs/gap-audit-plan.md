# 분류 갭 감사 계획 · 진행 기록

지도의 국면 분류(초기·중기·후기·완공)와 현실이 다른 사례를 **체계적으로 찾고, 원인을 유형별로 닫는** 작업.
원칙(사용자): 개별 수정보다 **원인 유형화 + 전체 필터**. 2026-09-08 두 세션에서 확인한 내용과 남은 일을 적는다.

## 0. 도구 (2026-09-08 2차 세션에서 구현)

| 도구 | 실행 | 하는 일 |
|---|---|---|
| 공용 분류 규칙 | `lib/stage.mjs` | 원자료 단계 → 보정(CORRECTIONS: useApr·built·doneBy·stale·cons·moved) → 표시 문자열 → 세부 단계(STAGE_RULES) → 국면. 앱(`lib/zones.ts` 가 타입만 입혀 재export)·설명 도구·감사가 **같은 함수**를 쓴다. `explainStage(p)` 가 어느 규칙이 결정했는지 돌려준다 |
| 설명 도구 | `node scripts/explain.mjs <no | 이름> [--fetch] [--all]` | 한 기록의 근거 층 10개: ① 원자료(캐시 목록과 일치 여부) ② 위치(locSrc·지오코딩 캐시) ③ 구역 연결(방법·검증·좌표가 든 다른 폴리곤이 왜 안 묶였는지·이름 유사 구역) ④ 서울주택정보마당 착공·이주 매칭(행별 점수, 누가 차지했는지, 준공 추정 조건) ⑤ 건축물대장 총괄표제부(하한·행마다 걸러진 조건) ⑥ V-World 건물 신호(후보 조건·동수·판정) ⑦ 옛 기록 ⑧ 최근 동향 ⑨ 최종 분류(규칙 id) ⑩ 정답 비교. 캐시만 읽어 네트워크 없이 돈다 |
| 정답 목록 | `data/truth.json` | `{ no, name, truth: 완공|진행|옛기록, note, checkedAt }` 19건(2026-09-08). name 은 참고용(바뀌면 경고) |
| 회귀 검사 | `npm run audit` (`--strict` 면 위반 시 종료코드 1) | 정답 vs 앱 분류 위반 목록 + 보정 규칙별 건수·정답 적중/오탐 + 놓친 준공. `build:data` 끝에서도 자동 실행(출력만) |
| 표본 추출 | `npm run audit -- --sample 20 --seed N` | 후기 단계(서울) 표본 점검표(markdown). `docs/sample-audit-2026-09-08.md` 에 20건 뽑아 둠 |

빌드 스크립트 `scripts/build-data.mjs` 는 이제 import 가능(직접 실행일 때만 `main()`). 규칙이 함수로 분리돼 explain 이 그대로 쓴다:
`housingScore`·`bestHousingMatch`·`doneByHousingEligible`, `registryEligible`·`registryMinDay`·`registryRowCheck`, `builtCandidacy`·`builtVerdict`, `compatible`·`digitsConflict`·`nameScore`·`staleNameRelation` 등.

## 1-2. 서울플랜+ 도시계획사업 전체 반영 (2026-09-08 4차)

서울플랜+ ArcGIS 레이어 UPIS_C_UQ120 의 도시계획사업 도형 2,982개(29종) 중 정비 성격 유형만 받아(`SEOULPLAN_TYPES`: 신통기획·재개발·재건축·주거환경·가로주택·자율주택·소규모재건축·소규모재개발·역세권 장기전세·역세권 활성화·촉진구역·공공주택지구·도심공공복합·도시개발·리모델링·시장정비; 미리내집·안심주택·촉진지구·존치·도시재생·사전협상 제외) `applySeoulPlan` 이 합친다.

- 기존 구역과 같은 도형(IoU ≥ 0.5)이면 새 도형을 만들지 않고, 그 구역에 연결된 사업장 → 도형 안 좌표 사업장 → 같은 구·같은 정규화 이름 사업장 순으로 유형이 맞는 정보몽땅 기록을 찾아 `plan{code,type,stage,date,history,ended}` 을 붙인다. 도형이 없던 사업장은 서울플랜+ 도형을 연결(zoneHow seoulplan).
- 맞는 기록이 없으면 source '서울플랜+' 기록을 만든다(no = PRESENT_SN 해시 12xxxxxx, 단계 = 서울플랜+ 추진단계 이름, 좌표 = 도형 중심).
- 라벨 둘째 항목(note)은 서울플랜+ 단계가 정보몽땅 단계보다 앞서거나 별도 트랙(신통·역세권활성화·도심복합 → "신통 기획완료")일 때만 바꾼다. 취소·중단 기록은 시행 이후·완료 사업장에 붙이지 않는다(옛 해제 구역이 준공 단지 자리에 남은 사례: 홍은13·신반포4지구).
- 단계 규칙 추가(lib/stage.mjs): cancelled(취소·해제·중단 → 완료·숨김), plan-early(기획완료·입안·열람·사전검토·위원회심의·지구지정 → 계획), pre-union(조합설립 추진 중·주민합의체 → 추진위), remodel-2nd(2차 안전진단 → 시행), 시행에 허가·실시계획, 완료에 사업완료·사용승인. 기존 기록 영향은 '도시계획심의' 2건이 시행→계획으로 바뀐 것뿐(의도).
- 보정 planEnd: 정보몽땅 기록에 붙은 서울플랜+ 단계가 취소·해제·중단이면 완공처럼 숨김.
- 갭 유형 후보: 서울플랜+ 도형이 정보몽땅 기록과 잘못 묶이는 경우(큰 신통 대상지 도형 안의 다른 사업) — `node scripts/explain.mjs <no>` ⑦-2 층으로 확인.

## 2. 남은 일

**C. 표본 감사(사람 확인)** — `docs/sample-audit-2026-09-08.md` 20건의 현실을 뉴스·지도로 확인해 `data/truth.json` 에 추가 → `npm run audit` 으로 규칙별 적중/오탐 숫자. 눈에 띄는 후보: 미아제3구역(11305023, '분양', 이름 연결 — 미아3촉진구역 11305019 와 다른 옛 사업일 가능성), 신반포22차(착공, 필지), 방배신동아(착공), 등촌1(착공), 노량진6(착공).

**F. 정답이 늘면** 보정 규칙 우선순위·하한(건축물대장 2018/2024, 건물 tall≥3) 재검토. 오탐이 나온 규칙은 explain 출력으로 조건을 좁힌다.

**G. 주간 갱신 러너** — `npm run audit` 은 build:data 끝에 출력만 한다. 위반이 반복되면 워크플로에 `--strict` 단계를 넣어 알림으로 쓸지 결정.
